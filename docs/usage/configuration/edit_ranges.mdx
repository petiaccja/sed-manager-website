# Editing locking ranges

:::warning Assigning a sector to a different locking range erases it

When you change which locking range a sector of your drive is assigned to, that sector's content will be erased. Because of this, you have to be extremely careful when editing locking ranges on a drive that already has data on it.

:::

You can change the following parameters of [locking ranges](/docs/theory/the_tcg_spec#locking-ranges):
- **Start**: the first LBA sector of the locking range
- **Length**: the number of LBA sectors in the locking range
- **End**: the last LBA sector of the locking range, which is itself not included in the range
- **Read lock enabled**: read access to the range will be blocked after power cycling the drive
- **Write lock enabled**: write access to the range will be blocked after power cycling the drive
- **Read locked**: read access to the range is currently blocked
- **Write locked**: write access to the range is currently blocked

Additionally, you can also **erase** the contents of the locking range. Erasure is instantanious as its implemented by crypto shredding.

:::tip Manufacturers may set predictable keys

There have been a several instances of manufacturers of various devices (WiFi routers, self-encrypting drives, etc.) setting predictable passwords in the factory that attackers could guess. To avoid this, you can generate new encryption keys by erasing locking ranges just before you configure your drive.

:::

## Alignment

Some drives require you to align the locking ranges to certain multiples of sectors. For example, if the alignment requirement is 8 sectors, a locking range starting at the 0th, 8th, or 16th LBA is correct, but a range starting at the 13th LBA will not be accepted by the device. SEDManager will automatically adjust alignment for you by rounding it down to the closest alignment boundary.

## Overlapping ranges

Except for the global range, ranges are not allowed to overlap. If you attempt to set overlapping ranges, the device will give you an *invalid parameter* error. In case you're changing multiple ranges at once, a helpful trick is to first set the length of all ranges to zero, as zero-length ranges will never overlap.

## Drives that don't support encryption

Locking ranges are still present on drives that don't support encryption. These drives will prevent access to the range's LBA sectors all the same, but this is merely a firmware protection, the data within the chips is still not encrypted. On such drives, the erase operation will fail as cryptographic erase is not possible. This currently only affects TCG Pyrite drives.

## How should I configure locking ranges?

- **You're the only one using the drive**: Enable both read and write locking for the global locking range.
- **You share the drive with others**: Assign a locking range to each user. Additionally, you can set up shared locking ranges.
